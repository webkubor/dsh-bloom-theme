## 一、视觉层级与材质原则

### [LES-01] 侧栏毛玻璃与包含块（Containing Block）陷阱
- **现象**：当直接在侧栏容器 `[class*="_sidebarCol"]` 上声明 `backdrop-filter: blur(...)` 时，侧栏内部的所有右键菜单、弹出气泡或固定定位元素（`position: fixed`）被异常截断在侧栏宽度内。
- **根因**：根据 CSS 规范，在元素上声明 `backdrop-filter`、`transform`、`filter` 或 `contain: paint` 时，该元素会自动成为后代 `position: fixed` 元素的包含块（containing block），破坏了视口绝对定位。
- **规范解法**：`backdrop-filter` 绝不声明在侧栏自身，统一通过 `::before` 伪元素（`position: absolute; inset: 0; z-index: -1`）承载毛玻璃背景。
- **索引**：`src/css/glass.ts` 侧栏背景实现。

### [LES-02] 去硬边框原则与侧栏分组间距控制
- **现象**：早期尝试在分组之间画横向边框或渐隐光带，导致侧栏被 18 条横线分割得像表格；但后续将 `_groupSection + _groupSection` 的 `margin-top` 设为 `16px` 时，又导致 Issue #102 中工作区文件夹之间垂直间距过大、极度空旷。
- **根因**：DSH 侧栏的分组不仅包含大类目，还包含连续的工作区文件夹。过大的外边距会严重稀释信息密度。
- **规范解法**：取消任何硬实线分割；分组间距收敛为紧凑的 `6px`，依赖组标题文件夹图标与条目层级缩进实现自然区分，兼顾透气感与信息密度。
- **索引**：`src/css/component.ts` 侧栏条目规则；关联 Issue #102。

### [LES-03] 顶栏下沿辉光与伪元素裁剪规避
- **现象**：使用 `header[class*="_header"]::after` 绘制顶栏下沿的渐变分割带时，下边界在 y=58 处产生生硬的明暗跳跃（截断线）。
- **根因**：伪元素受限于 header 本身的盒模型（border-box），渐变最浓的部分在边缘被硬性截断。
- **规范解法**：使用 `box-shadow: 0 28px 48px -28px color-mix(...)` 向外投射弥散辉光。外阴影在 border-box 外部自然衰减，两端无硬边。
- **索引**：`src/css/component.ts` 顶栏外阴影规则。

### [LES-04] 浅色多光源弥散光晕（Mesh Bloom）与中心阅读留白
- **现象**：浅色模式下若仅平铺单色或浅灰，界面显得单调冰冷；若全屏涂抹高饱和渐变，又导致聊天文字和代码块对比度下降、眼花缭乱。
- **根因**：单一色彩覆盖缺乏视觉层次与空间景深。
- **规范解法**：采用对角多光源漫反射渐变（Mesh Gradient）：
  1. 右上角（92% 10%）：主色柔光（`--bloom-motion-1` 26%），半透漫开。
  2. 左上角（8% 18%）：谐波色调（`--bloom-motion-2` 20%），形成冷暖交融。
  3. 中心与输入区：渐变快速衰减为 94%~96% 纯净莫兰迪珠白，保持正文对比度 ≥ 12:1。
- **索引**：`src/css/component.ts` 浅色 `--bloom-ambience` 规则。

### [LES-05] 暗色边框阶梯与前景色 Token 滥用反模式
- **现象**：暗色模式下，若使用前景色文字 Token（如 white / `--dsw-alias-label-primary`）加透明度作为边框或背景，界面发灰起雾，甚至导致发送按钮图标消失。
- **根因**：前景色是“光”，在暗色背景上叠半透明白会制造非预期的灰蒙蒙白霜；暗色的阴影和边框必须依赖深色莫兰迪色阶（`morandi` 气质轨）或纯黑衰减。
- **规范解法**：边框四档阶梯（l1～l4）在暗色下强制取 `morandi`，阴影强制使用黑底，实心控件填充严格取 `accent`。
- **索引**：`src/tokens.ts` borderStack / shadowStack。

## 二、宿主选择器与层叠避坑

### [LES-06] CSS Module 子串匹配污染与歧义排查
- **现象**：
  1. `[class*="_menu"]` 意外匹配了 `cubgiG_menuAnchor`，把按钮包裹层变成了绝对定位菜单。
  2. `[class*="_bubble"]` 意外匹配了全局气泡 Tooltip（`_bubble_1nw3t_1`），导致鼠标悬停提示框样式错乱。
- **根因**：属性子串包含选择器 `*=` 缺乏标签限制，且宿主不同组件存在命名重叠。
- **规范解法**：
  1. 必须限制元素标签：如 `div[class*="_bubble"]`、`button[class*="_newSession"]`。
  2. 显式排除包含关系的子串：`[class*="_menu"]:not([class*="_menuAnchor"])`。
  3. `scripts/check.mjs` 强制执行选择器歧义审查闸门。
- **索引**：`src/css/glass.ts`、`scripts/check.mjs`。

### [LES-07] 焦点环与 DSH Static 中性色覆盖
- **现象**：DSH 许多面板关闭按钮和选中态使用了 static 层的 `#adb2b8` 或浏览器默认蓝色焦点环，在莫兰迪主题下极度刺眼。
- **根因**：宿主绕过了 alias 抽象层，直接使用了底层的硬编码静态色值。
- **规范解法**：在主题中统一声明全局 `:focus-visible` 主题色微光轮廓，对特定选中状态（如深浅模式单选框）进行精准层叠覆盖。
- **索引**：`src/css/component.ts`、`src/css/switcher.ts`。

### [LES-08] 表格自适应容器与 md-table-wide 冲突规避
- **现象**：表格样式强加 `min-width: 100%` 导致宽表格戳破聊天气泡；或者与 DSH 0.2.1 的 `.md-table-wide` 修饰类产生选择器特异度竞争，导致横向滚动条抽搐。
- **根因**：DSH 表格使用自适应宽度分支，单属性选择器 `(0,1,0)` 会输给带类名的双重选择器 `(0,2,0)`。
- **规范解法**：使用多类选择器并列提升特异度，限定在 `[_tableScroll]` / `[_tablePane]` 内，依靠表格固有尺寸与外层包裹实现平滑滚动。
- **索引**：`src/css/component.ts` 表格规则；关联 Issue #62、#76。

## 三、运行时架构与生命周期

### [LES-09] 顶栏 overflow 裁剪与 shell.overlay 逃逸挂载
- **现象**：通过官方 Slot `conversation.header.leading` 挂载配色切换器时，下拉菜单被宿主顶栏的 `contain: paint` 和 `overflow: hidden` 截断，无法展示。
- **根因**：宿主顶栏容器限制了高度并裁剪溢出。
- **规范解法**：
  1. `conversation.header.leading` 仅作为占位与定位锚点（Anchor）。
  2. 菜单主体与全屏星辉层挂入顶层的 `shell.overlay` Slot。
  3. 通过 `ResizeObserver` 与 `requestAnimationFrame` 实时对齐锚点坐标，完美逃逸裁剪。
- **索引**：`src/ui.ts`、`src/switcher.ts` `mountSwitcher()`。

### [LES-10] 宿主背景覆盖与 body::before 氛围层隔离
- **现象**：桌面端真机运行时，`body` 的计算背景常被宿主简写属性 `background:` 破坏或覆盖为透明。
- **根因**：宿主 SPA 页面路由切换时可能重置顶层内联样式。
- **规范解法**：所有全屏氛围与弥散光均挂在 `body[data-bloom-variant]::before`（`position: fixed; inset: 0; z-index: 0`），不受 body 内联样式变更波及。
- **索引**：`src/css/component.ts`。

### [LES-11] 插件停用卸载与全局事件/定时器 100% 幂等回收
- **现象**：在 DSH 插件管理器中停用插件后，样式标签、菜单 DOM、定时器与窗口监听器依然滞留在宿主中，必须强制重启宿主。
- **根因**：早期直接在模块顶层执行 IIFE 注入，缺乏受控的生命周期 Disposer。
- **规范解法**：
  1. 所有副作用严格托管至 `ctx.effect`。
  2. 集中定义 `teardownBloom()`，清理全部 `<style>`、DOM 节点、ResizeObserver、定时器、全局监听器与 `window.__BLOOM_DEBUG__`。
  3. 配备 `test/lifecycle.test.mjs` 全生命周期自动化断言。
- **索引**：`src/teardown.ts`、`test/lifecycle.test.mjs`。

### [LES-12] 星辉情境化档位与中央阅读区径向遮罩保护
- **现象**：
  1. 过去星辉光点被硬编码限制在右上角一个 `360×220px` 的局促区域内，在宽屏或大窗口下显得极为小气、缺乏氛围感。
  2. 若直接让光点漫布全屏，当用户阅读长消息流或编写代码时，不断漂移闪烁的光点会干扰文字排版与视线焦点。
- **根因**：缺乏对用户视觉情境的分层控制，且全屏粒子层缺乏对高频阅读内容区域的保护机制。
- **规范解法**：
  1. 提供 4 档极简情境切换：`对角漫染`（默认，右上主星云 + 左下微星尘，呼应水彩弥散光晕）、`漫天星河`（全屏漫布星尘）、`角落微光`（仅右上角）、`关闭`。
  2. 采用 CSS `mask-image: radial-gradient(...)` 动态给粒子容器施加中央椭圆羽化遮罩：屏幕中央 50% 核心阅读区域粒子透明度强制衰减为 0，光点仅在四周边缘、卡片缝隙和顶栏自然漂移，兼得视觉小惊艳与阅读零干扰。
- **索引**：`src/starlight.ts`、`src/css/glass.ts`。

### [LES-13] 侧栏横向滚动条
- **现象**：会话行悬停时出现横向滚动条。
- **根因**：悬停 `translateX(2px)` 让行宽超出列表宽度。
- **规范解法**：侧栏行只做底色淡染与按下微缩，不做位移；会话列表 `overflow-x: hidden`。
- **索引**：`src/css/component.ts`；回归见 `test/surface-regression.test.mjs`。

### [LES-14] 浅色液态玻璃与通透背景
- **现象**：浅色背景曾用弧形光带模拟示例图，出现明显边界，像“一道线”。
- **根因**：把“组件的玻璃折射”误放到了背景层。
- **规范解法**：背景只做主题色到白色的平滑渐变，不出现任何硬边；玻璃感全部落在组件上：
  白色半透明面（左上亮、右下薄）+ 渐变高光描边 + 大范围主题色柔影。
  只在浅色且材质为“通透”时生效，“柔和/实底”与系统“降低透明度”沿用 adaptive.ts。
- **索引**：`src/css/liquid.ts`、`src/css/component.ts` 浅色氛围段。

### [LES-15] 输入区底板盖住氛围
- **现象**：浅色新会话页顶部一条主题色带、下方整片平灰，带有明显边界。
- **根因**：`_composerSeat::before` 只铺了不透明底色；新会话页里这块底板几乎占满正文区，把 body 的氛围渐变挡住。
- **规范解法**：底板在不透明底色上重画同一份 `--bloom-ambience`，`background-attachment: fixed` 按视口定位，与 body 层无缝衔接。
- **索引**：`src/css/component.ts` §1.5。

### [LES-16] 改浅色不得影响深色
- **现象**：做浅色玻璃与深色档位时，顺手加了深色星云背景、改了星点颜色与分布，深色观感比 v0.26.0 退步。
- **根因**：新档位直接改写深色共享样式，没有把「已认可的深色」当作基线保护。
- **规范解法**：深色默认档「角落微光」与 v0.26.0 逐项一致（同一种子与参数、像素锚定右上 360×220、白点与主题色点）；
  其余深色档位只在这一簇之上叠加星点，深色背景与面板在任何档位下都不变。
  改动前后用同一夹具注入新旧 CSS，对 12 个配色比较计算样式。
- **索引**：`src/starlight.ts`、`src/css/glass.ts` 星辉段；回归见 `test/starlight.test.mjs`。

### [LES-17] 漫天流星
- **现象**：「漫天星河」只是多撒一些白点，颜色单一，看不出「漫天」，也没有流动感。
- **规范解法**：改为「漫天流星」：40 道流星从顶边与右边斜向左下划过全屏，亮头 + 主题色渐隐尾，
  颜色轮流取当前配色的三段光谱（motion-1/2/3）；星尘同步换成主题色光谱。流星每个周期亮约 20%，
  保持稀疏不刷屏；正文区遮罩为 25% 而非全透明；减弱动效时不显示流星。仅深色、仅此一档。
- **索引**：`src/starlight.ts` makeMeteor、`src/css/glass.ts` 星辉段。

### [LES-18] 浅色玻璃看不出来
- **现象**：浅色面板在近白背景上看起来就是白卡片，用户「看不出哪里有玻璃感」。
- **根因**：玻璃靠「透出背后的颜色 + 边缘折光」被感知；背后是白色时模糊没有内容可折射，填充又偏实，等于一张白纸。
- **规范解法**：① 在面板背后（输入框、侧栏位置）放柔和的主题色光斑，给玻璃可折射的内容，整体仍从主题色过渡到白、无硬边；
  ② 面板填充降到约 10~30% 白，加左上斜向镜面高光；③ 1.5px 渐变折光描边（白 → 主题光谱 → 白），
  下/右内沿主题色暗边表现厚度；④ 模糊沿用统一 token、饱和度提高，让背后颜色清楚透出；⑤ 主题色浮影加深。
- **索引**：`src/css/liquid.ts`、`src/css/component.ts` 浅色「斜光流转」。
- 补充：侧栏内层 `_root` 自带不透明填充，会把玻璃盖成平板，液态玻璃档下置为透明。

### [LES-19] 浅色背景的弧线与边框双线
- **现象**：① 浅色背景出现一条斜向硬边界（像直线平铺）；② 面板边框看起来有两条线，脏。
- **根因**：① 半径不够大的 radial-gradient，其衰减终点在屏幕上呈一条弧线；② 渐变描边（border RIM）与
  盒阴影里的 inset 边线（DEPTH/EDGE 各一条）叠加，一圈就画出两条线。
- **规范解法**：① 浅色主体过渡只允许 linear-gradient（线性无弧线）；色斑必须超大半径（≥140%）+ 极低
  透明度 + 从 0% 就开始衰减；② 每个面板只允许一条边线：Bloom 自有面板用 border 渐变描边，
  宿主面板用单层 inset 描边；DEPTH 只保留大 blur 的体积光，不再画边。
- **索引**：`src/css/component.ts` 浅色氛围段、`src/css/liquid.ts`。

### [LES-20] 液态玻璃的本质：边缘折射，不是整片磨砂
- **现象**：均匀 backdrop-blur 的面板读作「磨砂白板」，无论怎么调描边都没有液态玻璃感。
- **失败方案**：曾用 13px 高饱和模糊环模拟折射，结果是厚边和灰脏；收成 2px 后仍只有描边。此方案废弃，采用 [LES-27] 的边缘位移；不能再把模糊与饱和度增强称为折射。
- **索引**：`src/css/liquid.ts`。

### [LES-21] 浅色 hover 粗框与打字扫光
- **现象**：输入框 hover 边框明显变粗变脏；打字时横向掠过的主题光效在浅色上是一块灰蓝色污渍。
- **根因**：hover 把描边从 hairline 提到 hairline-strong（液态玻璃的薄边下格外突兀）；
  扫光带 34% 不透明横向色块是为深色设计的流星感，浅色上没有对比可依附。
- **规范解法**：浅色非实底档 hover 只轻微提亮外辉，不加重描边；
  浅色打字光改为左上角 9% 透明度的呼吸光晕（不位移），深色保留扫光；折射环 13px→2px。
- **索引**：`src/css/component.ts` 打字光段与 hover 段、`src/css/liquid.ts`。
- 补充 [LES-20]：发送键在玻璃风格里不能是平的实心圆——做成主题色宝石透镜：左上白高光 + 深色底缘 + 内圈亮边 + 主题色外辉，按下有受压感。
- 补充 [LES-08]：非 md-table 的普通滚动容器（轨迹 tab 区）同样遵循「平时透明、悬停显色」；空内容时长紫条不许常驻。

### [LES-22] 跨代码块的通用问题必须只写在台账
- **现象**：同类问题在不同文件里反复出现（多处滚动条常驻、多处边框双层、多处"深色专用效果漏到浅色"），
  但教训只散落在单个代码块的注释里，下次在别的代码块照样再犯。
- **规范**（owner 2026-11-07 定则）：
  1. **通用问题一律只写在本台账**，按现象→根因→规范解法成条；代码里最多留一行 `[LES-xx]` 索引。
  2. 新写任何视觉规则前，先查本台账是否已有同类条目；有就复用编号，不新写注释。
  3. 台账条目必须写成"适用所有代码块"的判定规则，不是某个文件的修改记录。
- **索引**：本文件全部条目。

### [LES-23] 空内容时常驻的滚动条滑块
- **现象**：轨迹 tab 区、空会话区出现一条常驻的紫色长滑块（978px 宽的截图里横贯底部）。
- **根因**：主题只处理了 `md-table-wide` 的滚动条显隐，普通滚动容器（`_scroll`/`_tableScroll`/`_tablePane`
  的非 wide 分支）的滑块仍然常驻。
- **规范解法**：所有滚动容器统一「几何保留、滑块平时全透明、容器悬停或聚焦才显色」；
  空内容时视觉上不允许出现任何色块。适用一切代码块，不只表格。
- **索引**：`src/css/component.ts` [LES-08b] 段。

### [LES-24] 浅色模式的"通透"含义
- **定义**：通透 = 背景是主题色到白的平滑线性渐变（无弧线无色带），面板中心 8~34% 白染色透出背景色，
  边缘一圈窄折射环。它**不是**"什么都不显示"，也不是把内容区留成空框。
- **反例**（2026-11-07 用户实拍）：把主内容区做成一个空边框、只有一条滚动条 —— 那是宿主空状态
  （该会话无消息）+ 滚动条常驻滑块叠加出来的错觉，不是通透档本身。
- **规范**：诊断"通透模式啥都没有"类反馈时，先区分：宿主空状态 / 滚动条滑块常驻（[LES-23]）/
  氛围层真的没画。三者修法完全不同。
- **索引**：`src/css/component.ts` 浅色氛围段、`src/css/liquid.ts`。

### [LES-25] 玻璃配方一处定义、处处复用
- **现象**：输入框做出了液态玻璃，但侧栏、顶栏、图标按钮各是各的旧样式，整页观感不统一。
- **规范**：液态玻璃是一组固定配方（中心白染色 + 边缘折射 + 单条描边 + 主题色浮影 + 玻璃小珠按钮），
  在 liquid.ts 里一处定义、按选择器复用到所有面板与按钮；新面板接入只加选择器，不重写配方。
  宿主在侧栏/顶栏内的不透明底一律置空让路。
- **索引**：`src/css/liquid.ts`。

### [LES-26] 浅色"脏"的三个来源
- **现象**：浅色整页粉灰发泥；输入框上方一条横向色带；顶栏下、侧栏边各一道分界。
- **根因**：① 多个不同色相、20%+ 浓度的大色团在正文区叠加，混出灰色；② 底板伪元素在浅色下仍有不透明底色并重画氛围，`background-attachment: fixed` 在带遮罩的伪元素上不按视口计算，渐变压缩在小盒内；③ 顶栏 tab 白底 + 底线、侧栏灰色外投影，在彩色底上各成一条硬边。
- **规范**：浅色氛围以白色为主，主色平滑过渡，不在正文区叠加多个异色色团。不能把底色压得几乎纯白后，再要求同样偏白的材质可见。输入区遮挡用一层带渐隐的亮色底托，避免滚动文字被模糊成脏块；不在局部重复绘制整页渐变。分隔交给同一套材质边缘，不叠加宿主灰线。

### [LES-27] 玻璃需要光学效果、可见轮廓与真实截图共同成立
- **现象**：24px 模糊、白染色和一条细线在平滑白底上几乎不可辨；去掉所有高光又让面板消失。给主容器加滤镜与 `position: static` 还破坏了菜单锚点及 fixed 浮层。
- **规范**：低模糊保留中央细节；内联 SVG displacement map 只弯曲边缘，中心位移为零。共享填色与方向性高光，侧栏和顶栏只调整装饰伪元素的留白、圆角，不重排宿主内容。滤镜只放在装饰层，不能过滤包含 fixed 后代的主容器；不能给文字内容加 mask。
- **坐标陷阱**：0×0 定义 SVG 中的 feImage 必须使用 objectBoundingBox 坐标（宽高 1），位移比例也随之归一化。误用百分比会让位移贴图失效、全图统一偏移。中性通道需校准 128/255 与 0.5 的差值。
- **证据**：液态镜片像素测试在中心得到平均 RGB 差 0、边缘差约 30.22；布局测试覆盖菜单锚点、fixed 后代、伪元素位置、侧栏文字。光学测试通过不能代替视觉验收；2026-11-07 的 r3 两路评审不一致，不能称为多模型通过。
- **索引**：`src/liquid-lens.ts`、`src/css/liquid.ts`、`test/liquid-lens.test.mjs`、`test/liquid-layout.test.mjs`。

### [LES-28] 桌面调试必须可重复，不能用浏览器副本冒充
- **失败路径**：读取桌面 Cookie 后启动 headless 页面、直接改 body 属性、把 9230 Host Inspector 当 Electron CDP、依赖旧窗口 id 或固定屏幕坐标，均不能证明当前桌面通过。原生 Console 长脚本也未稳定；异步读取 DevTools copy 要先保存引用，剪贴板必须在所有出口恢复。
- **成功路径**：通过 macOS Accessibility 读取/按下真实 Bloom 菜单，检查选中状态与当前触发器名称；从 CGWindowList 动态取得主窗口，再 screencapture。2026-11-07 已真实执行橙黄、黛蓝、桃夭 × 深浅六组，并恢复粉霞/浅色/水彩晕染/通透；未操作消息输入框。
- **覆盖计数**：菜单有 12 配色 × 2 明暗 × 4 对应氛围 × 3 显式材质，共 288 组；自动跟随系统是额外的偏好/媒体查询测试，不把不存在的第四个菜单按钮算进原生覆盖。
- **索引**：项目 `skills/bloom-desktop-ui/SKILL.md`、`scripts/ui/native-ui.swift`、`scripts/ui/native-matrix.py`。成功步骤写 skill；失败路径只留在本台账，不保留为默认入口。
- **异步与恢复**：AXPress 成功并不等于 aria 状态已经更新，需有上限地等待 readback。记录并恢复深浅各自的氛围，不能只恢复当前可见一组；隐式 auto 与显式 glass 无法仅靠 AX 区分，必须披露。

### [LES-29] 不把无效光学试验反复装到用户桌面
- **现象**：r5 真实截图上的玻璃辨识度仍存在评审分歧，技术像素测试通过不足以说明审美通过。
- **对照结论（2026-11-07）**：A 的弱白色 bevel 只略微清理边缘；B 的较强主题色反光更像描边。C 在 alpha 高度图上添加 specularLighting，5,184,000 像素仅 717 个变化，最大 RGB 差 2/255，肉眼无改善。D 保留材质只加同色光团，提供了一点透明参照，却产生灰蓝软斑，输入框仍无改善。
- **规范**：这些方案只在隔离 Web 临时 DOM 对照，没有进入源码、候选包或桌面。没有明确整体改善就不推广；不能轮流强化描边、加光团、再抹平来回兜圈。后续先证明真实启用的输入框、菜单覆盖内容等场景有可见且干净的材质差异，再改通用配方。
- **证据位置**：`/tmp/bloom-ui/glass-prototypes/`；r5 两路独立评审均给出需修改，实际远端模型未确认，不能宣称多模型一致通过。

### [LES-30] 焦点样式只保留一条清晰边缘
- **现象**：选中项自身描边与键盘焦点阴影叠加，鼠标点击也留下粗边。
- **规范**：选中态和焦点态分别处理；键盘焦点保留可辨识的单条轮廓，跟随宿主指针模式和强制颜色设置。

### [LES-31] 原生验收前记录完整状态
- **规范**：操作菜单前记录当前窗口、外观、材质偏好、两套背景和自动轮换档位；AX 中的有效显示值不能证明隐式自动偏好。原状态不明时不猜测还原；用户交互期间及时停止并保留草稿。窗口与截图位置每次动态读取。截取合成画面前后都要确认目标窗口在前台；一旦焦点或窗口发生变化，先删除本次截图而不是打开。只需检查窗口自身时，优先按窗口 ID 截图，注明它不能证明屏幕合成效果。

### [LES-32] 只读诊断的输入与页面归属
- **规范**：先发现官方 Inspect Provider，再传符合 schema 的 JSON 对象；不要把对象编码成字符串。多个桌面页面可能同时报告焦点，须同时核对 origin、页面 ID 和原生 AX 编辑器与 DOM 编辑器的坐标/宽度，才能把样式和原生截图归为同一窗口。诊断只返回布局、样式和输入长度，不返回正文或草稿。

### [LES-33] 材质、背景与配色各自负责一件事
- **规范**：三个材质是明暗共用的偏好；浅深背景分别保存，背景形态不改变材质。浅色背景以当前皮肤主色配协调色形成自然渐变，逐渐过渡到白；颜色不局限于同一色相，也不把固定配色误当成通用方案。多层色场必须控制叠加，避免灰脏和突变横带。本条更新 [LES-26] 的单色限制。

### [LES-34] 光效必须与真实输入状态同步
- **规范**：空闲时浅色输入光效不得启动；输入开始后才启用，结束后停止。减少动态效果与强制颜色应取消不必要的动画。

### [LES-35] 按钮的玻璃样式覆盖所有可见状态
- **规范**：玻璃按钮应有可辨的半透圆面、柔和高光和清晰图标；启用、悬停、禁用和宿主发送中状态分别核对，不能只测试启用状态。强制颜色和高对比度必须可读。

### [LES-36] 共享样式必须按生产层叠顺序验证
- **现象**：局部材质测试通过，但后注入的共享表面层覆盖了磨砂颗粒，并让三种材质的填色和边缘相同。
- **规范**：用生产注入顺序检查真实计算样式和像素；侧栏、顶栏、输入卡及底栏都要验证材质差异、透明度、文字清晰度和 fixed 后代。截图和实机目视不能由局部 CSS 测试替代。

### [LES-37] 捕获 API 存在不等于桌面可用
- **现象**：桌面运行时暴露了 `getDisplayMedia` 与 `MediaRecorder`，但在真实菜单点击截图和录屏均未出现屏幕选择器，提示授权未获得或已取消；使用模拟流的浏览器测试仍然全部通过。
- **规范**：区分 API 存在、系统选择器实际显示、用户授权成功和文件可用四个证据层级，不把其中一项当作其他项的证明。截图或录屏只能由用户触发并由用户选择来源，失败时停在清晰提示，不能绕过系统许可；静态代码线索不能单独证明具体拒绝原因。

### [LES-38] 固定底板与深色背景必须逐像素衔接
- **现象**：输入区底板只画纯色，页面却绘制主题渐变，部分配色因此出现明显横向色阶；即便某种配色更明显，问题也可能影响整个体系。
- **规范**：让页面和固定底板使用同一套按视口定位的颜色与渐变，并避免重复叠加导致色值偏差。核对宿主 `html[data-platform] body` 背景清除规则与输入区 `will-change: transform`：前者可能让页面渐变失效，后者可能改变固定背景的定位坐标。用包含宿主 CSS 的空白夹具按两种注入顺序逐色比较底板显示前后的同位置像素，设置有效负控，同时检查文字对比度、关闭背景和既有粒子动效；最后还须核对真实页面像素和观感。

### [LES-39] 演示素材要为「为什么用它」服务
- **现象**：发布要求「README 有视频和特色图」，第一版只录了 6.5 秒星空空镜；技术上真实、隐私干净，用户立即否掉：没有面板操作、配色切换、材质与明暗对比，回答不了「这版为什么值得装」。
- **规范**：先列本版真正亮点并写成镜头脚本（谁看、要说服什么），再录制；素材产出后自问能否说服没用过它的人。演示观众是不了解产品的用户，不是 CI 或发布流程本身。该教训已升级为全局准则：不要做执行机器。

### [LES-40] 展示素材链接用版本锚点
- **现象**：README 首版素材链接指向 `raw.githubusercontent.com/.../main/...`，文件合入前 404，合入后又随 main 漂移，历史版本 README 会指向未来被改动或删除的文件。
- **规范**：对外素材链接统一锚定不可变 ref（发布 tag 或 commit），文件名带完整版本；合入前核对链接可达性策略，合入后复查真实 URL。注意 URL 写 tag 在 PR 阶段同样 404，须在 Release 合并并打 tag 后统一验证，README 里不得出现「待补」字样混过关。
