# 排障：主题不生效、按钮看不清、插件装不上

面向使用者的常见问题处理。开发细节见 [lessons.md](lessons.md)（宿主兼容踩坑台账）与
[diagnostics.md](diagnostics.md)（诊断与信息导出）。

## 主题装了但看不出变化

1. **确认版本真的换了。** 打开顶栏的主题按钮，面板底部会显示当前生效的 `Bloom v0.x.y`；
   这个数字来自插件自身，不是缓存。若仍是旧版本，见下一节。
2. **完全退出再打开。** Cmd+Q 退出应用再重开；只关窗口不算退出。
   主题样式在应用启动时注入，热重载不一定能替换已经渲染的节点。
3. **确认没被关掉。** 主题可能已被停用或卸载：在「插件」列表里看 Bloom 是否处于启用状态。

## 版本更新后仍显示旧版

Bloom 只在应用启动后做一次版本检测，并且**检查失败时不会打扰你**；若刚检查过一次，
24 小时内不会再次联网检查。宿主更新较慢时，可能要等到下一个检查周期才看到提示。

因此新版本发布后，短时间内仍显示旧版是正常现象，不是更新失败。

- 应用内提示「有更新」时，点击「立即更新」即可；桌面端不支持原地更新时，按提示到
  「插件」管理里更新对应 profile。
- 也可以手动更新：

  ```sh
  dsh plugin --profile <your-profile> add dsh-bloom-theme@latest
  ```

  `dsh plugin` 会把其余参数转交给 pnpm 在 profile 目录里执行。

### 先确认你看的是哪个 profile

**桌面端、Web 端和自建 profile 各自独立安装插件，互不影响。** 同一个机器上完全可能出现
「桌面端已经是新版，某个 profile 还是旧版」的情况——两个界面显示的版本号不一样，不是
哪一边出错。逐个 profile 查看当前版本：

```sh
dsh plugin --profile <your-profile> list
```

输出里 `dsh-bloom-theme@<version>` 就是该 profile 实际安装的版本。确认是哪个 profile
装旧了，再针对它执行上面的更新命令。

## 某个插件的按钮文字看不清

如果**别的插件**面板上的主按钮或选中标签变成实色块、文字几乎不可见，多半不是插件之间
「冲突」，而是主题改动了宿主的语义 token。历史上真实发生过一次：主题把主按钮填充色
`fill` 与其上的文字色 `dimmed` 都派生自强调色，导致两者同色相。

这种情况的处理方式：

1. 先把主题更新到最新版本（该问题在 0.9.1 已修复）。
2. 更新后按上一节的做法完全退出并重开应用。
3. 若仍有问题，请在 [issues](https://github.com/webkubor/dsh-bloom-theme/issues) 反馈，
   并附上：Bloom 版本、宿主版本、哪个插件的哪个界面、亮色还是暗色。

反馈时请用面板里的「诊断」按钮导出信息，它会生成可直接粘贴的 Markdown 折叠块，
比截图更能定位问题。

## 插件装不上

- **确认包名。** npm 上的包名是 `dsh-bloom-theme`，没有作用域前缀。
  早期版本曾用过 `@kubor/dsh-bloom-theme`，该名字在 npm 上**已不存在**，按它安装会报
  404。部分第三方目录的旧快照仍在推荐这个旧名，看到带 `@kubor/` 的安装命令请直接换成
  `dsh-bloom-theme`。
- **确认 profile 装对了。** 桌面端、CLI 与自建 profile 各自独立；装在 A profile
  不会影响 B profile。想确认装在哪里：

  ```sh
  dsh plugin --profile <your-profile> list
  ```

- **零运行时依赖。** 本插件没有额外依赖，安装不需要 `--ignore-scripts` 之类的特殊参数。

## 配色看起来和预期不一样

主菜单 12 套配色各自带明暗两套，面板里的「外观」可以单独选浅色、深色或跟随系统。
如果切换后界面没变，先确认当前配色档位本身是否被记忆成上一次的取值，再试一次手动切换。

## 反馈问题时请附上

- Bloom 版本（面板底部显示）与宿主版本；
- 使用的配色名与明暗档位；
- 复现步骤；
- 「诊断」按钮导出的信息块。
