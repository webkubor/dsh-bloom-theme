# 排障：主题不生效、按钮看不清、插件装不上

[English](troubleshooting.en.md)

面向使用者的常见问题处理。开发细节见 [lessons.md](lessons.md)（宿主兼容踩坑台账）与
[diagnostics.md](diagnostics.md)（诊断与信息导出）。

## 主题装了但看不出变化

1. **确认版本真的换了。** 打开顶栏的主题按钮，面板底部会显示当前生效的 `Bloom v0.x.y`；
   这个数字来自插件自身，不是缓存。若仍是旧版本，见下一节。
2. **完全退出再打开。** Cmd+Q 退出应用再重开；只关窗口不算退出。
   主题样式在应用启动时注入，热重载不一定能替换已经渲染的节点。
3. **确认没被关掉。** 主题可能已被停用或卸载：在「插件」列表里看 Bloom 是否处于启用状态。

## 版本更新后仍显示旧版

先分清两件事：

- **没看到「有更新」提示**：Bloom 在应用启动后检查一次新版本，检查失败时不打扰你；
  若上次检查结果已是最新，24 小时内不会再联网检查。所以新版刚发布时可能暂时没有提示。
- **更新过了，面板底部仍显示旧版本**：面板上的版本号是**当前加载的插件包**自带的版本，
  和检查周期无关，等待不会让它变化。这说明新版本没有装到你正在用的那个 profile，
  或应用还没完全重启（Cmd+Q 后重开）。

更新方式按你用的入口选：

- **桌面端 app**：在侧栏「插件」管理里更新，或点更新提示里的「立即更新」。桌面端的
  profile 由应用托管，`dsh plugin --profile desktop` 会被 CLI 拒绝，不要用终端命令。
- **Web 端或自建 CLI profile**：先查最新版本号，再显式安装该版本：

  ```sh
  npm view dsh-bloom-theme version
  dsh plugin --profile <your-profile> add dsh-bloom-theme@<上面查到的版本号>
  ```

  写明版本号比 `@latest` 更可靠：某些 profile 的锁文件已解析到旧版本时，`@latest`
  可能不会真的升级。`dsh plugin` 会把其余参数转交给 pnpm 在 profile 目录里执行。

### 先确认你看的是哪个 profile

**桌面端、Web 端和自建 profile 各自独立安装插件，互不影响。** 同一台机器上完全可能出现
「桌面端已经是新版，Web 端还是旧版」——两个界面显示的版本号不一样，不是哪一边出错。

- 桌面端：看面板底部的 `Bloom v0.x.y`，或「插件」管理里的版本。
- Web 端或自建 CLI profile：

  ```sh
  dsh plugin --profile <your-profile> list
  ```

  输出里的 `dsh-bloom-theme@<version>` 就是该 profile 实际安装的版本。

## DeepSeek Harness 更新后主题样式异常

Bloom 通过 DeepSeek Harness 界面里的样式类名定位各个区域。宿主更新后如果改了这些名字，
**部分区域会静默失去 Bloom 样式**：不会报错，界面也能正常使用，只是某块恢复成默认外观或配色不协调。
Bloom 要求的宿主最低版本写在 `package.json` 的 `engines.dsh` 中，宿主版本不满足时可能无法安装或启用插件。

按顺序处理：

1. **先把 Bloom 更新到最新版本**，做法见上文「版本更新后仍显示旧版」。新版本通常会跟进宿主的界面变化。
2. **完全退出应用后重开**（macOS 上 Cmd+Q），确认面板底部显示的是新版本号。
3. 仍有异常但影响使用时，可以先停用 Bloom：桌面端在侧栏「插件」管理中关闭；
   Web 端或自建 CLI profile 可执行 `dsh plugin --profile <your-profile> remove dsh-bloom-theme`。
   界面会回到宿主默认外观，之后可以重新安装。
4. 到 [Issues](https://github.com/webkubor/dsh-bloom-theme/issues) 反馈，附上 Bloom 版本、宿主版本、
   异常区域的截图以及「诊断」导出的信息块。

## 某个插件的按钮文字看不清

如果**别的插件**面板上的主按钮或选中标签变成实色块、文字几乎不可见，多半不是插件之间
「冲突」，而是主题改动了宿主的语义 token。历史上真实发生过一次：主题把主按钮填充色
`fill` 与其上的文字色 `dimmed` 都派生自强调色，导致两者同色相。

这种情况的处理方式：

1. 先把主题更新到最新版本（该问题在 0.9.1 已修复）。
2. 更新后按上一节的做法完全退出并重开应用。
3. 若仍有问题，请在 [issues](https://github.com/webkubor/dsh-bloom-theme/issues) 反馈，
   并附上：Bloom 版本、宿主版本、哪个插件的哪个界面、亮色还是暗色。

反馈时请用面板里的「诊断」按钮导出信息，它会生成可直接粘贴的 Markdown 折叠块，
比截图更能定位问题。

## 插件装不上

- **确认包名。** npm 上的包名是 `dsh-bloom-theme`，没有作用域前缀。
  早期版本曾用过 `@kubor/dsh-bloom-theme`，该名字在 npm 上**已不存在**，按它安装会报
  404。部分第三方目录的旧快照仍在推荐这个旧名，看到带 `@kubor/` 的安装命令请直接换成
  `dsh-bloom-theme`。
- **确认 profile 装对了。** 桌面端、Web 端与自建 profile 各自独立；装在 A profile
  不会影响 B profile。查看方式见上文「先确认你看的是哪个 profile」。

- **零运行时依赖。** 本插件没有额外依赖，安装不需要 `--ignore-scripts` 之类的特殊参数。

## 配色看起来和预期不一样

主菜单 12 套配色各自带明暗两套，面板里的「外观」可以单独选浅色、深色或跟随系统。
如果切换后界面没变，先确认当前配色档位本身是否被记忆成上一次的取值，再试一次手动切换。

## 如何调整玻璃质感

打开顶栏的 Bloom 主题按钮，在面板的「质感」分组中选择「毛玻璃」「磨砂玻璃」或「液态玻璃」。配色可在同一面板的「主题」分组切换，浅色、深色或跟随系统在「模式」分组调整。

如果系统开启降低透明度，尚未显式选择材质的自动档会显示为实底；手动选择三种材质之一后，单独的降低透明度设置不会覆盖你的选择。系统启用强制颜色或高对比度时则优先使用实底。诊断中的 `glassMode` 是保存的偏好，可能与实际生效效果不同。
